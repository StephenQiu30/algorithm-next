# 排序教学修复与发布

排序实现、轨迹、身份与伪代码行映射的唯一来源是 `src/lib/sortingAlgorithms.ts`。`lib/algorithms` 仅为兼容导出。

执行步骤游标表示已执行的事件数：0 为原始输入，第 1 步为首个事件，N 为完成。重播、回退与切换算法保留原始问题；只有“重新生成”或长度滑杆生成新数组。比较只计元素值比较，交换不计同一位置，归并剩余复制只计写入；写入统计写回主数组，辅助缓冲区构造另计。教学轨迹的快照存储开销独立于算法空间复杂度。

练习包含预测操作及数组、执行反馈、概念题和本机进度。目标由首次答对的不同步骤及概念回答决定，不由播放次数决定。本机记录不具备跨设备同步；它不是正式测评成绩。

## 课程发布

1. 修改 `_content` 教程或排序引擎后运行 `npm run course:build`。
2. 将 `course-release` 中 8 份 Markdown 作为同一课程发布包上传。每份文档使用 manifest 中的 name、version、bizTag。旧 `algorithm-cloud/docs` 中的独立教程不作为本课程发布源。
3. 待后台显示文档 COMPLETED 后，在该知识库召回分析页粘贴 `golden-questions.json`，运行批量检查。版本与文档命中率、MRR 是召回证据；真实问答仍需对照参考答案核验。
4. 前台课程版本由发布包内容计算，CI 用 `course:check` 防止源文件与发布包漂移。AI 请求按算法和该版本过滤；未上传相应版本时不会混用旧课件。联网搜索默认关闭，开启后来源会明确标记。

## 后端部署顺序

先执行 `algorithm-cloud/sql/migrations/20260930_chunk_publication.sql`（一次性），再部署新 AI 服务。新字段保存完整课程元数据。重新处理文档时，新构建使用独立向量 ID，同步确认关键词索引后，用数据库事务切换分片清单。两个检索通道都只接受清单中的已发布分片；失败构建和残留旧索引不能参与回答。读取、向量化、关键词或 DB 失败均保留旧清单。

新会话键使用 `rag:v2:<登录用户>:<知识库>:<客户端标签哈希>`。客户端提供标签不能访问其他身份的记忆；旧未隔离记忆不迁移到新命名空间。
